# Web UI 設計

本文件定義 PartsRadarTW 第一版網站的頁面、使用流程與資料顯示規則。第一版先專注於查詢、瀏覽與篩選原價屋商品資料，不做行銷首頁、會員功能或通知功能。

## 設計原則

- 首頁就是商品查詢工具，不另外做 landing page。
- 介面以快速搜尋、篩選與掃描價格為主。
- 第一版採 table-first 查詢工具，不做 marketplace 式大型卡片瀏覽。
- 所有商品資料都要能看出主要商品圖片、來源、目前價格與最後有效更新時間。
- 使用者可以從網站回到原價屋來源頁確認最新資訊。
- crawler 失敗時不清空畫面，網站顯示最後一次成功處理的有效資料。
- 資料可能過期時要提示，但不阻擋使用者查詢既有資料。
- 來源狀態只代表 crawler、parser 與來源資料同步健康度，不代表商品是否可購買。
- 第一版不顯示 raw snapshot、parser error 或 crawler 內部細節。

## Route Overview

第一版網站先包含：

| Route | 頁面 | 用途 |
| --- | --- | --- |
| `/` | 商品查詢頁 | 搜尋、分類瀏覽、篩選、排序與分頁 |
| `/products/{id}` | 商品詳細頁 | 查看單一商品價格、來源與狀態 |

第一版不建立：

- 登入頁。
- 會員中心。
- 價格提醒設定頁。
- 收藏清單頁。
- 購物車或購買流程頁。
- 商品比較頁。
- 價格歷史圖表頁。
- 後台管理頁。

## 首頁 / 商品查詢頁

`/` 是第一版主要頁面，預設載入商品列表。

主要區塊：

- 搜尋輸入框。
- 分類篩選。
- 價格區間篩選。
- 排序選單。
- 資料來源狀態提示。
- table-first 商品資料表。
- 分頁。

### 搜尋

搜尋行為：

- 使用 `q` 查詢商品名稱與 normalized name。
- 搜尋字串應保留在 URL query，方便分享與重新整理。
- 空搜尋代表顯示目前篩選條件下的商品列表。
- 搜尋沒有結果時顯示空狀態，不視為錯誤。

URL query 範例：

```text
/?q=7800x3d
```

### 分類篩選

分類來源：

- `GET /api/categories`

篩選行為：

- 使用 `igrp` 作為分類 query。
- 分類選單顯示 API 回傳的 `displayName`。
- 需要保留來源脈絡時，可在較低干擾位置顯示原價屋 `sourceName`。
- 未選分類時顯示全部第一版支援分類。
- 分類切換後保留搜尋字串與排序。
- 分類切換後頁碼回到第 1 頁。

URL query 範例：

```text
/?igrp=4
```

### 價格篩選

價格篩選使用目前價格。

篩選欄位：

- 最低價格。
- 最高價格。

規則：

- 價格以整數 TWD 輸入。
- `minPrice` 不可大於 `maxPrice`。
- 不合法輸入不送出查詢，並在欄位旁顯示簡短提示。
- 價格篩選變更後頁碼回到第 1 頁。

URL query 範例：

```text
/?igrp=4&minPrice=3000&maxPrice=10000
```

### 排序

排序來源：

- `GET /api/products` 的 `sort` query。

第一版排序選項：

- 價格低到高：`price_asc`。
- 價格高到低：`price_desc`。
- 名稱 A 到 Z：`name_asc`。
- 最近看到時間新到舊：`updated_desc`。

預設排序：

- `price_asc`

### 商品資料表

商品資料表每筆至少顯示：

- 主要商品圖片。
- 商品名稱。
- 分類。
- 目前價格。
- 幣別。
- 最後看到時間。
- 來源狀態或資料狀態。
- 原價屋來源連結。

主資訊順序應以商品圖片、商品名稱、分類、目前價格、最後更新或最後看到時間、來源狀態、來源連結為主。圖片縮圖需固定尺寸與比例，避免 table row 因載入狀態或缺圖而跳動。broken image、loading 或 temporary fallback 只是容錯設計，不代表第一版資料契約可以沒有商品圖片。

行為：

- 點商品名稱進入商品詳細頁。
- 點來源連結開啟原價屋分類頁。
- 第一版來源連結不保證能直接定位到單一商品。
- 預設只顯示 active 商品。
- 若使用者選擇包含下架或暫時消失商品，才顯示 inactive 商品。
- inactive 商品需顯示明確狀態，不應和一般商品混在一起而沒有標示。
- inactive 商品可提示「此商品目前可能已下架或暫時未出現在來源頁」，但不得宣稱商品是否可購買。

規格副文字：

- 第一版不把規格副文字作為必要資訊。
- 若目前 parser 只能取得原始商品名稱，UI 不應假裝有品牌、腳位、晶片組、容量、瓦數等結構化欄位。
- 不應在 Phase 05 先設計硬體規格篩選；若未來要補規格解析，應另開 phase 或文件決策。

第一版不在商品列表顯示：

- 價格歷史圖。
- 價格提醒按鈕。
- 收藏按鈕。
- 加入購物車按鈕。
- 規格展開表。

### 分頁

分頁使用 page-based pagination。

規則：

- 預設 `page=1`。
- 預設 `pageSize=24`。
- 使用者可前往上一頁、下一頁與指定頁碼。
- 篩選條件改變時頁碼回到第 1 頁。
- 第一版不做 infinite scroll。

## 商品詳細頁

`/products/{id}` 顯示單一商品的目前狀態。

資料來源：

- `GET /api/products/{id}`

顯示內容：

- 商品名稱。
- 主要商品圖片。
- 分類。
- 目前價格。
- 幣別。
- 價格更新時間。
- 最後看到時間。
- 第一次看到時間。
- 原價屋來源連結。
- 商品目前是否 active。

行為：

- 商品存在但 inactive 時仍顯示詳細頁。
- inactive 商品需提示「此商品目前可能已下架或暫時未出現在來源頁」。
- 商品不存在時顯示 404 頁或查無商品狀態。
- 原價屋來源連結不包含 `PHPSESSID`。
- 第一版來源連結指向原價屋分類頁，不保證能直接定位到單一商品。
- 主要商品圖片需顯示在詳細頁；缺圖 fallback 只作為容錯，不是正常完成狀態。

第一版不顯示：

- 價格歷史清單。
- 價格歷史圖表。
- 價格提醒設定。
- 商品規格欄位；第一版只完整顯示原始商品名稱。
- raw snapshot 或 crawler error。

## 資料來源狀態

網站透過 `GET /api/source-status` 判斷資料狀態。未套用分類篩選時使用全域狀態；使用 `igrp` 篩選時，優先顯示該分類的狀態，避免某個其他分類過期時干擾目前查詢。

來源狀態只表示 CoolPC crawler、parser 與來源資料同步是否正常，不代表單一商品是否可購買。商品列表中的狀態欄應命名為「來源狀態」或「資料狀態」。

### `ok`

顯示方式：

- 商品列表與詳細頁正常顯示。
- 可在頁面低干擾位置顯示「最近成功檢查時間」。

### `stale`

顯示方式：

- 商品仍可查詢。
- 商品列表頁上方顯示低干擾提示，告知最近未成功檢查來源，目前仍顯示最後一次有效價格。
- 商品詳細頁在價格附近以低干擾文字顯示最近成功檢查時間。
- 若全域狀態為 `stale` 但目前篩選分類是 `ok`，頁面可只顯示分類層級的正常狀態，不必提示整站過期。

提示內容應避免過度驚嚇使用者，只需表達最近未成功檢查來源；不要暗示原價屋價格本身應該更頻繁更新。

### `unavailable`

顯示方式：

- 若沒有任何有效商品資料，顯示目前沒有可用資料。
- 不顯示空商品列表讓使用者誤以為是查詢條件造成無結果。
- 可提示稍後再試。

## 空狀態與錯誤狀態

### 查無商品

發生條件：

- API 成功回傳，但 `data` 為空。

顯示方式：

- 顯示查無符合條件的商品。
- 保留目前搜尋與篩選條件。
- 提供清除篩選條件的操作。

### 查詢參數錯誤

發生條件：

- API 回傳 `400`。

顯示方式：

- 在對應欄位顯示錯誤。
- 不顯示技術錯誤內容。
- 使用者修正條件後可重新查詢。

### 商品不存在

發生條件：

- 商品詳細 API 回傳 `404`。

顯示方式：

- 顯示找不到商品。
- 提供返回商品查詢頁的操作。

### API 錯誤

發生條件：

- API 回傳 `500` 或前端請求失敗。

顯示方式：

- 顯示資料暫時無法載入。
- 不顯示 stack trace 或內部錯誤內容。
- 若頁面已有舊資料，不應因重新載入失敗而誤顯示為商品不存在。

## URL State

商品查詢頁的主要狀態應反映在 URL query。

URL query 包含：

- `q`
- `igrp`
- `minPrice`
- `maxPrice`
- `sort`
- `page`
- `pageSize`
- `status`

目的：

- 支援重新整理後保留查詢條件。
- 支援分享搜尋結果連結。
- 減少前端狀態與 API 查詢條件不一致。

## RWD 行為

第一版至少支援桌面與手機版 RWD。

桌面版：

- 搜尋與篩選控制可集中在列表上方。
- 商品列表可用表格或緊湊列表呈現。
- 價格、分類、最後看到時間應容易掃描。
- 商品圖片固定尺寸，價格欄固定對齊。

手機版：

- 搜尋框優先顯示。
- 篩選控制可收合。
- 商品項目改為垂直排列。
- 價格與商品名稱優先顯示。
- 商品圖片仍需顯示，但不得擠壓價格與商品名稱。

## 第一版不做的 UI

第一版不處理：

- 使用者登入與帳號設定。
- 個人價格提醒。
- Discord bot 設定。
- 收藏商品。
- 商品比較。
- 購物車、下單或自動購買。
- 價格歷史圖表。
- 管理者後台。
- crawler 異常細節頁。
- raw snapshot 檢視頁。
