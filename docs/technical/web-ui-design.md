# Web UI 設計

第一版網站是查詢工具，不是 landing page、marketplace 或會員服務。UI 只讀 API 已處理的資料，資料與安全規則以 [API 設計](api-design.md) 和 [資安基準](security.md) 為準。

## 設計原則

- 首頁就是商品查詢頁。
- Table-first / dense list 體驗，優先支援搜尋、篩選、排序、掃描價格。
- 每筆商品需看得到主要圖片、名稱、分類、目前價格、資料狀態與來源連結。
- 使用者可見價格統一顯示為 `NT$ 12,345`；使用者可見時間固定使用 `Asia/Taipei`。
- crawler 失敗時不清空畫面；顯示最後一次成功處理的資料與低干擾 stale 提示。
- 來源狀態只代表 crawler / parser / source data sync，不代表商品可購買。
- 不顯示 raw snapshot、parse error 或 crawler internal details。

## Routes

| Route | 頁面 | 用途 |
| --- | --- | --- |
| `/` | 商品查詢頁 | 搜尋、分類、廠商、價格、排序、分頁 |
| `/products/{id}` | 商品詳細頁 | 單一商品價格、來源、狀態與外部連結 |

第一版不建立登入、收藏、提醒、比較、購物車、後台、價格歷史圖或 raw snapshot viewer。

## 商品查詢頁

主要控制：

- 搜尋輸入。
- 分類篩選。
- 廠商複選。
- 最低 / 最高價格。
- 排序。
- active / inactive / all 狀態。
- 分頁。

URL state：

```text
q, category, vendors, minPrice, maxPrice, sort, page, pageSize, status
```

規則：

- URL query 可分享與重新整理。
- `category` 使用產品語意 slug，例如 `cpu`、`gpu`；公開 URL 不產生 CoolPC `igrp`。
- 只有 legacy `igrp` 時前端以 `history.replaceState` 轉成 canonical `category` URL，不重新載入頁面。
- 無有效 `category` 時前端落到第一個支援分類。
- 切換分類時清除廠商選項並回到第 1 頁。
- 價格輸入需是整數 TWD；`minPrice > maxPrice` 時不送出查詢。
- 搜尋無結果是空狀態，不是錯誤。

排序：

- `price_asc`
- `price_desc`
- `name_asc`

預設排序：`price_asc`。

## 商品資料列

列表每筆至少顯示：

- 固定尺寸主要商品圖片。
- 商品名稱。
- 分類。
- 目前價格與幣別。
- 價格最後確認時間。
- 來源 / 資料狀態。
- 原價屋查看 / 購買連結。

圖片規則：

- 前端使用站內圖片 API：`/api/product-images/{productId}.webp`。
- 不以 CoolPC hotlink 作為正式完成狀態。
- 圖片載入失敗、無圖或檔案不存在時，縮圖區域仍保持固定尺寸並顯示 fallback。
- fallback 不假設圖片來源一定是 CoolPC domain。

Inactive 規則：

- 預設列表只顯示 active 商品。
- 使用者選擇 inactive / all 時才顯示 inactive。
- inactive 文字需表達「可能已下架或暫時未出現在來源頁」，不得宣稱是否可購買。

第一版不在列表顯示：

- 價格歷史圖。
- 提醒 / 收藏 / 比較 / 購物功能。
- 結構化硬體規格或規格篩選。

## 商品詳細頁

資料來源：`GET /api/products/{id}`。

顯示：

- 主要商品圖片。
- 原始商品名稱。
- 分類。
- 目前價格、幣別、價格時間。
- inactive 商品的最後出現時間。
- active / inactive 狀態。
- 原價屋查看 / 購買連結。

規則：

- 商品存在但 inactive 仍顯示詳細頁。
- 商品 404 使用「找不到這項商品，或目前無法公開顯示」等中性文案，不把下架當成唯一原因。
- 來源連結不包含 `PHPSESSID`。
- 複製連結只寫入不含 query state 的 canonical 商品 URL；不啟動平台專屬分享流程。
- 商品 metadata / Open Graph 標題需在整體長度限制內保留可讀的商品名、目前價格與站名；描述以自然中文呈現分類、目前價格、台北更新時間與公開來源邊界，canonical 不包含 query state。
- 商品詳細主資料不顯示拆解規格、raw snapshot 或 crawler error。

## 第二版價格歷史區塊

資料來源：`GET /api/products/{id}/price-history`。

設計方向：

- 參考本地 `price.png` 的資訊架構，但不提交該參考圖。
- 價格數字是主角；控制項與圖表線條服務於判讀價格，不應比價格本身更搶眼。
- 使用資料工作台風格：深色底、少量高對比價格色、清楚分區、低裝飾。
- 第二版不再擴充成股票工具或複雜分析介面。

顯示：

- 近 7 / 30 / 90 天與全部時間價格走勢。
- 期間變動、最低、最高、均價摘要。
- 商品詳情頁上方商品資訊負責顯示目前價格；價格走勢區塊負責期間變化與區間摘要。
- 區間位置條：顯示目前價格落在最低到最高之間的位置。
- 區間價格變化金額與百分比。
- 時間範圍切換：`7 天`、`30 天`、`90 天`、`全部`，使用 segmented control。
- hover / tap tooltip：顯示價格、日期與來源類型，例如價格變動或價格確認。
- 變價紀錄列表：列出最近價格變動日期、前後價格、變化金額與漲跌狀態。
- 載入中與載入失敗狀態。

規則：

- 價格歷史載入失敗時，不應讓商品詳細頁整頁失敗。
- 若只有 1 筆價格 snapshot，但目前價格後續有被 crawler 再次確認，畫成水平線。
- 圖表只描述已收錄價格 snapshot 與目前價格確認點，不暗示來源站更新頻率保證。
- 第二版價格歷史互動控制只保留時間範圍與 tooltip。
- 不新增接近歷史低點提示、價格 / 漲跌幅模式、觀測點來源切換、Y 軸縮放或最低 / 最高 / 目前標記切換。
- 暫不做自訂日期區間、多商品疊圖、均線、技術指標或折線 / 柱狀 / 面積圖樣式切換。
- 不加入帳號、收藏、個人提醒或通知入口。

## 第二版配單

目標：讓使用者把查到的商品整理成一次性配單，並可匯出 Excel。

規則：

- 商品列表與商品詳情頁都應有「加入配單」入口。
- localStorage v2 最多保存 50 筆 `productId`、數量、加入／更新時間與顯式排序；不保存商品 snapshot、不讀取或轉換 v1。配單只存在目前瀏覽器，不建立帳號或 server-side 個人清單。
- 進入配單頁時以單次批次 request 取得目前名稱、圖片、分類、價格、來源連結與上架狀態，並提供最近成功同步時間與手動重新整理。網路錯誤、`429` 或部分 missing 不得刪除 intent。
- inactive 且仍有價格的商品顯示「可能已下架」並可計價；missing、refresh 失敗或無價格的品項保留數量／排序，價格不計入總價，summary 顯示未計價品項數。
- 商品列表與詳情頁在已有 50 個不同品項時，不接受第 51 個品項；既有品項仍可增加至單列數量上限。
- Excel 匯出使用當次 refresh 結果，包含 product ID、商品狀態、配單同步時間、來源連結與備註；未知列保留 ID／數量／狀態並留空價格、小計。檔名與內容時間固定 `Asia/Taipei`，worksheet freeze 首列並啟用 filter。
- 配單 summary 只說明估算與未計價語意；來源、購買與售後聲明由全站 footer 負責。
- 手機版配單入口、數量調整、移除品項與匯出動作不可造成水平溢出。
- 不做自動推薦配單、相容性檢查、帳號保存菜單或使用者通知。

## 來源狀態

來源狀態顯示優先使用目前分類狀態；沒有分類時可使用全域狀態。

| 狀態 | UI 行為 |
| --- | --- |
| `ok` | 正常顯示，可低干擾顯示最近成功檢查時間。 |
| `stale` | 繼續顯示最後有效資料，提示最近未成功檢查來源。 |
| `unavailable` | 若沒有任何有效資料，顯示目前沒有可用資料，不誤當查無商品。 |

提示文字需避免暗示原價屋價格必須更頻繁更新。

## 空狀態與錯誤

| 情境 | 行為 |
| --- | --- |
| 查無商品 | 保留條件，提供清除篩選。 |
| Query 400 | 在對應欄位顯示簡短錯誤，不顯示技術細節。 |
| API 429 | 顯示「瀏覽速度較快，請稍後再試。」；保留可重試狀態，不顯示技術細節。 |
| 商品 404 | 顯示找不到商品，提供回查詢頁。 |
| API 500 / fetch failed | 顯示資料暫時無法載入；若已有舊資料，不誤顯示成商品不存在。 |

## RWD

桌面：

- 篩選與排序集中在列表上方或側欄。
- 價格、分類、時間容易掃描。
- 圖片與價格欄尺寸穩定。

手機：

- 搜尋優先。
- 篩選可收合。
- 商品列改成垂直資訊層級。
- 圖片仍顯示，但不得擠壓名稱與價格。

## 公開前聲明

第一版 footer 需說明：

- PartsRadarTW 是非官方、非商業商品搜尋與價格整理工具。
- 資料來源為原價屋公開頁面。
- 實際商品資訊、價格、庫存、購買與售後以來源頁為準。

UI 不建立使用者可修改資料入口或管理後台。
