# Phase 05 視覺語言草案

本文件根據專案根目錄的 `style.png` 示意圖整理 Phase 05 Web UI 的視覺方向。該圖片只作為風格參考，不作為一比一臨摹稿；實作時仍需依 PartsRadarTW 的實際資料、API contract、第一版功能邊界與原價屋公開資料來源限制調整。

本文件只描述設計語言與排版理解，不定義 crawler、database、API 或圖片 metadata 的技術實作。

## 視覺定位

PartsRadarTW 的第一版網站應該是深色、現代、工具型的硬體查詢介面，而不是行銷首頁、一般電商首頁或 Discord bot 控制台。

整體感覺接近硬體監控台、價格雷達與資料查詢工作台：使用者進站後立即能搜尋、篩選、比較價格與判讀資料新鮮度。畫面應該讓人覺得這是一個可重複使用的查詢工具，而不是一次性瀏覽頁。

新版參考圖已降低單一介面臨摹感，方向更偏 table-first 的產品操作面板：上方提供狀態摘要，中段左側承載查詢條件，主要區域用資料表呈現商品。後續實作應抽取這種資訊層級與工具感，而不是複製圖中的每個欄位、數字、圖示或控制項。

## 可保留的設計語言

- 深色基底：以黑藍、炭黑、深灰作為主要背景，降低長時間查詢的視覺疲勞。
- Cyan / blue accent：用於 active tab、目前價格、重要操作與資料狀態重點。
- 細線與低對比邊界：用分隔線、輕微背景層次與 hover state 區分區塊，避免厚重卡片感。
- 高資訊密度：畫面要能同時呈現搜尋、分類、篩選、商品資料表、價格與來源狀態。
- 工具列式操作：搜尋、排序、分頁、每頁筆數與篩選套用應像查詢工具的控制列，而不是行銷 CTA。
- 資料表優先：主要畫面以 table / dense list hybrid 為中心，讓商品、分類、價格、最後更新與來源狀態能快速掃描。
- 價格強調：目前價格是列表中最強的視覺重點，應高對比、易掃描。
- 狀態輔助：資料狀態使用短文字、色點與低干擾提示，不用大面積警告區塊干擾查詢。
- Icon 輔助掃描：分類、來源、外部連結、排序與篩選可使用 icon，但 icon 不應取代必要文字。
- 現代科技感：可用透明感、細緻陰影與柔和 glow，但應克制，避免變成遊戲 RGB 或裝飾性背景。

## 不應照抄的部分

- 不做登入、帳號、通知鈴、收藏書籤等 Phase 05 明確不包含的功能。
- 不顯示購物、加入清單、追蹤清單或提醒設定入口。
- 不顯示商品供應承諾；來源狀態只描述 crawler、parser 與來源資料同步健康度。
- 不假裝有商品規格解析；第一版若沒有結構化規格欄位，應以原始商品名稱與價格資訊為主。
- 不把範例圖中的商品數量、分類數、同步時間或更新頻率當成真實產品承諾。
- 不做單純展示用 hero；首頁第一屏應直接是查詢工具。
- 不因參考圖有摘要卡片就擴張成 dashboard 首頁；摘要只能服務查詢與資料狀態判讀。
- 不回到 marketplace 或大型卡片瀏覽 layout；第一版核心是查詢工作台。

## 首頁排版方向

桌面版首頁建議採四層結構：

1. Top bar：品牌、主要導覽、全站搜尋、來源更新狀態。
2. Summary strip：用少量摘要指標顯示已收錄分類、資料筆數、最後同步與來源狀態。
3. Work area toolbar：顯示搜尋結果數、排序、每頁筆數與必要的檢視控制。
4. Work area：左側篩選欄加右側商品資料表。

若需要快速切換分類，可以使用橫向 category rail 或左側分類 checkbox，但不必同時做兩套主要分類入口。新版參考方向更適合把分類放在左側篩選，讓主視覺留給資料表。

Summary strip 應克制，最多呈現和查詢可信度直接相關的摘要，例如分類數、商品筆數、最後同步與來源狀態。它不是 KPI dashboard，不應加入轉換率、熱門商品或行銷型數字。

左側篩選欄應承載分類、價格範圍、來源狀態與清除 / 套用篩選等控制。右側商品資料表應是主要閱讀區，列表行固定節奏，避免每筆商品變成獨立大型卡片。

手機版不應硬塞桌面左欄。建議保留搜尋優先、分類可橫向滑動，其他篩選收進可展開的 filter panel 或 drawer。商品項目在手機上可轉成較高的 list item，但仍保持價格與狀態易掃描。

## 商品資料表語言

每筆商品的閱讀順序應是：

1. 主要商品圖片。
2. 商品名稱。
3. 分類。
4. 目前價格。
5. 最後更新或最後看到時間。
6. 來源狀態。
7. 來源。

商品圖片是必要資訊，應服務辨識，不應主導版面。列表縮圖需固定尺寸、固定比例，避免 table row 因載入狀態或圖片錯誤而跳動。缺圖 fallback 只能作為容錯設計，不是正常狀態。

商品名稱可能很長，資料表中以主要名稱為主；若要顯示副文字，應保持低權重且不承諾結構化規格。超出時截斷或進詳情頁閱讀完整名稱。價格欄要固定對齊，方便使用者上下比較。

桌面版可採欄位式資料表：商品、分類、目前價格、最後更新、來源狀態、來源。手機版可轉成同一資訊順序的 stacked list item，但仍要維持價格與狀態的位置一致。

## 商品詳細頁語言

商品詳細頁應延續列表的深色工具感，而不是變成電商商品銷售頁。

主要內容應包含：

- 商品名稱。
- 主要商品圖片。
- 目前價格。
- 分類與來源。
- 最後看到時間、價格擷取時間、第一次看到時間。
- active / inactive 狀態。
- 前往原價屋來源頁的外部連結。

詳細頁可以有更大的圖片與價格區，但不應加入購買流程、收藏、提醒、比較或價格歷史圖，除非未來 phase 明確納入。圖片不應壓過商品名稱與目前價格。

## 狀態呈現

`ok` 狀態應保持低干擾，只顯示最近成功檢查時間或小型狀態點。語意限於資料擷取與解析健康度。

`stale` 狀態應顯示目前仍在使用最後一次有效資料，避免讓使用者誤以為查無商品。提示要清楚但克制，不應使用大面積紅色錯誤樣式。

`unavailable` 狀態代表目前沒有可用資料，應顯示獨立空狀態，不要混同於搜尋條件查無商品。

`inactive` 商品應在列表與詳情頁都有明確標示，語氣應是「可能已下架或暫時未出現在來源頁」，不要宣稱商品確定不可購買。

## 色彩與層次

建議色彩方向：

- Base：接近 `#06111a`、`#0b1620` 的深色背景。
- Surface：比背景略亮的深灰藍，用於 top bar、filter panel、summary strip、table header 與 row hover。
- Border：低對比藍灰細線。
- Accent：cyan / electric blue，用於 active、價格與主要焦點。
- Success：綠色小點或短文字，用於來源資料正常。
- Warning：琥珀色或柔和黃，用於 stale、inactive 或資料較舊提示。
- Error：只保留給 API 錯誤，不用於一般 stale。

整體應避免單一藍色鋪滿整頁。深色背景可以是主調，但 cyan 只能作為重點，不應讓所有元件都發光。

## 字體與密度

字體應偏現代、清楚、工具型。商品名稱、表頭與價格要有足夠對比，但不使用過大的 hero 字級。

建議層級：

- 品牌與頁面主狀態：中等尺寸，高權重。
- Summary 數字：可略大，但只用於少量狀態摘要。
- 商品名稱：資料表中清楚但克制。
- 價格：商品 row 中最醒目的文字。
- metadata：較小、低對比，但仍需可讀。
- 狀態標籤：短、固定位置，不擠壓商品名稱。

資料表 row 高要服務掃描；不要把每個商品做成過高的展示卡。

## 互動語言

互動應快速、安靜、可預測：

- hover row 顯示輕微背景變化。
- active filter / category 有明確 accent。
- loading 狀態使用 skeleton 或低干擾 shimmer。
- filter drawer 開合應平順，但不需要誇張動效。
- 外部來源連結要有明確 icon 與可點擊範圍。
- 表頭排序與分頁操作要清楚，但不需要複雜的資料表設定功能。

動畫只應用來強化層級與狀態轉換，不應成為視覺主角。

## 設計邊界

此風格確認後，Phase 05 的 UI 實作應以「網站查詢工具」為主，不加入未納入 roadmap 的功能。商品圖片已屬於第一版資料需求；進入 UI 實作前需確認圖片來源、缺圖 fallback、API 欄位與安全限制。
